  Qué cambié

  connector/main.py — el callback ahora parsea el JSON y lo postea a la API:

  - MASTER_API_URL (default http://master:8000, el nombre del servicio en la red
    interna de Docker) + /events.
  - Ack manual (auto_ack=False + basic_qos(prefetch_count=1)): el ack solo se
    manda cuando el master confirmó que guardó. Antes, con auto_ack=True, si la
    API fallaba el evento se perdía.
  - Manejo de errores en tres ramas:
    - JSON inválido → ack (descartar, nunca va a servir).
    - 4xx del master (ej. 422 por schema) → log del body + ack. Reintentar no
      cambiaría el resultado y evita un loop infinito.
    - 5xx o red caída → sleep + nack(requeue=True), el evento vuelve a la cola.

  connector/requirements.txt — agregué requests.

  docker-compose.yaml — MASTER_API_URL y depends_on: master en el connector.

  Dos cosas que vale la pena que sepas

  1. El endpoint es /events, no /event (master/app/api/routes/events.py:11). Usé
  el que existe.

  2. La tabla events_raw no guarda el evento crudo. El route hace
  event.model_dump(), así que el Event de Pydantic filtra todo campo que no esté
  declarado. De los mensajes reales del broker se están perdiendo:

  - msgId (el identificador único del mensaje)
  - timestamp (cuándo se generó el evento)
  - demands[].code ("HGW", "COR", …)

  Para una tabla llamada raw eso es contraintuitivo, y timestamp/msgId te van a
  hacer falta para deduplicar y ordenar. Si querés, lo arreglo: o agrego esos
  campos al schema, o guardo el body crudo (await request.json()) y dejo el
  Pydantic solo como validación.

  Sobre el batch

  Con un evento cada 30s no lo necesitás por throughput. La razón real para
  hacerlo sería otra: requests.post es bloqueante dentro del callback de pika,
  así que mientras esperás al master no se procesan heartbeats. Con timeout=5
  estás muy lejos del heartbeat default (60s), así que hoy no es problema. Yo lo
  dejaría simple hasta que el volumen lo justifique.
